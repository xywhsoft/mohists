# 使用墨者

墨者是可选的协作 Agent。选择“墨者 · Mohists”后，可以直接提问；简单问题由协调者完成，需要分工时才创建任务组。研究、执行、复核成员各有自己的上下文，同一成员可以连续接收多轮任务。

## 安装与兼容

源码包只含插件 C 源码、角色、前端和说明，不包含 mdo 程序、账号、模型密钥或开发会话。解压 ZIP，在 mdo 的“插件”页面导入解压后的目录并启用，然后按提示重启。更新也使用同一插件 ID；回滚选择保留的上一个版本。

需要包含 `mdo-runtime.json` 所列源码基线的 mdo。ABI 1 本身不足以证明兼容：还必须支持持久成员主讲路由、真实成员历史、`session.execution` 和 `session.mark_external_state`。不支持的旧宿主会明确拒绝加载。当前源码基线尚不能当成已公开发布的客户端版本。

`python tools/package.py` 生成可复现的作者源码 ZIP 和校验清单。将来生成创作中心/本地生态导入文件时，需要明确提供兼容宿主的安装编号，例如 `--min-build-id <build_id>`。不要使用语义版本编码替代 build_id，也不要把开发宿主的编号当成已发布的兼容承诺。

## 协作窗口

从会话标题栏打开“墨者协作”，查看任务、成员、预算和当前主讲。点击任务可打开成员的原生历史，包括完整正文、工具调用与工具结果。历史来自实际执行，不是协调者转贴的摘要。

“默认设置”保存本机偏好：自动按需分工或仅由用户开始、复核方式、并发、累计成员轮次、角色与模型。新任务组复制这些偏好；已有任务组保持自己的配置。角色可以绑定已安装的配置式或 C Agent/SubAgent。成员创建后绑定固定；可以继续调整本组预算和复核方式，已使用轮次不会清零。

给成员的定向消息是被动邮箱，不会仅因收信就执行任务；执行需要明确提交并运行任务。成员不能代替用户提升权限、修改预算或确认不确定副作用。

## 主讲交接

成员已有上下文并处于空闲状态时，用户可点击“让此成员主讲”。之后主输入在该成员中执行，沿用其模型、历史和工具权限，真实输出进入主聊天。模型栏显示成员绑定，Token 面板使用该成员的用量；不改写协调者的模型配置。点击“返回协调者”可恢复原来的执行入口，草稿保留。

交接需要用户明确操作，模型不能自行接管。运行中、存在未决写入或预算不足时，系统会解释拒绝原因。返回协调者时提供成员历史引用；不会假装协调者已经拥有其他成员的完整上下文。

## 停止与恢复

停止会先关闭新任务准入，再取消活跃成员。重启不会自动重放模型或工具。存在未确定结果的工具操作时，成员和任务保留“需确认”，由用户查看原生恢复信息后决定继续、记录不确定结果或放弃。恢复也计入累计成员轮次。

成员未知的写入结果没有确认前，其他写入任务不能继续，以免重复修改。取消任务、修订目标和重启均不会把这种状态隐藏为普通成功或取消。

## 数据与当前边界

停用或卸载插件只移除执行入口和资源覆盖，原生会话、成员历史、任务和消息仍保存在本机 mdo Home；重新安装同一插件后可继续读取。更新、回滚也不会恢复旧的用户任务状态。删除整个 Home 会删除这些数据，请勿把它当成卸载步骤。

包含成员主讲记录的主聊天有多个原生账本。当前不支持同时改写这些账本的编辑重试、清空与分叉；界面隐藏对应入口，宿主会在修改前拒绝这些操作。新增输入、实际成员历史、交接和明确恢复仍可使用。远程会话应在所选设备执行；不支持把同一团队成员分布到多台设备。

协作任务和成员上下文位于会话目录以外，当前便携会话格式还不能完整打包这些数据。开始协作时会留下持久声明，完整备份、旧模型导出与设备间传输明确拒绝不完整采集；停用插件后仍保留保护。保存整个 mdo Home 可以保留这些数据。Markdown 导出用于阅读可见聊天，不代表可恢复的成员上下文；也不要手动删除声明文件来绕过保护。
