# 墨者实施记录

## 已确认范围

插件 ID `mohists`，提供协调者、研究员、执行者、复核者；角色和模型可以替换。默认最多三个活跃成员，一个协作范围内最多一个写入成员。原生用户权限始终有效。简单任务无需创建成员，不强制固定流水线。

成员复用、多轮任务、定向消息、独立上下文、取消和停止、累积预算、约束修订与过期结果、显式恢复、不确定副作用不自动重放，均为本轮范围。聊天需要主会话、成员列表、真实成员历史、用户定向输入、显式主讲交接与返回协调者。远程会话在目标设备执行。

使用现有插件安装、启停、更新、卸载和创作中心分发。通用能力缺口只补公开 SDK，不增加私有宿主接口。不建设调试、追踪、检测平台，不实现递归团队、跨设备团队或新的工作流引擎。

## 开发约束

在 `D:\GIT\mohists` 单线程开发，直接在项目目录测试。不创建隔离环境或仓库副本，宿主与 SDK 引用已有 mdo，仅部署约 9 MiB 应用文件到唯一运行目录。每个小阶段测试通过后提交 commit。禁止把密钥、生产数据、用户会话放入插件或仓库。

## 2026-10-26：显式中断恢复

- `refresh` 仅收取已有的原生结果；没有完成收据时标为 requires_review，不重放模型或工具。
- `resume`、`abandon` 要求用户决策及当前任务/成员 revision；模型工具拒绝代替用户作出恢复决策。恢复沿用原生工具副作用判断和 decisions，不复制用户输入。
- 累计成员轮次预算跨宿主重启保留，显式恢复计入新轮次；陈旧恢复请求不会消耗预算，放弃不会调用模型。
- `tests/test_recovery.py` 在唯一开发实例中真实终止并重启两次，验证不重放、明确恢复、无调用放弃和后续成员复用。
- 仍未完成：自动队列调度、协作界面、成员历史公开接口、真实主讲交接与完整分发回归。

## 2026-10-26：后台队列

- `run` 只启动明确请求运行的任务；事务先预留名额和累计预算，再使用已保存 ID 的原生 operation 执行。重复按钮或窗口意图复用准入状态。
- 默认三个活跃成员、一个写入成员，依赖任务完成后继续调度。`wait` 使用事件等待；协调队列不发出额外模型请求。
- 全局原生操作资源不足时回退为排队，不消耗成员轮次预算。只回收墨者专用 worker 的已完成句柄，保留原生成员结果和不相关的操作。
- 原有同步执行、取消、恢复测试保持通过。`tests/test_scheduler.py` 验证六项任务、重复运行、依赖推进以及八个原生操作占满后恢复。
- 界面与最终生产验收仍未完成，不应将当前代码称为完整可发布版本。

## 2026-10-26：界面操作边界与自定义角色

- 自定义角色绑定不能扩大研究员、复核者的只读能力；前置工具拒绝返回模型后可以继续回复。使用真实可写工具请求验证未写文件，第二轮模型正常完成，并保存失败工具记录。
- 窗口操作可携带 expected_generation，旧窗口不能取消新任务组的同名任务；历史显式选择 generation，避免误读新成员。
- 状态快照提供任务概要和 revision；组合输入在创建任务前检查原生邮箱上限，取消不会吞掉未决副作用的显式恢复入口。
