# 墨者实施记录

## 已确认范围

插件 ID `mohists`，提供协调者、研究员、执行者、复核者；角色和模型可以替换。默认最多三个活跃成员，一个协作范围内最多一个写入成员。原生用户权限始终有效。简单任务无需创建成员，不强制固定流水线。

成员复用、多轮任务、定向消息、独立上下文、取消和停止、累积预算、约束修订与过期结果、显式恢复、不确定副作用不自动重放，均为本轮范围。聊天需要主会话、成员列表、真实成员历史、用户定向输入、显式主讲交接与返回协调者。远程会话在目标设备执行。

使用现有插件安装、启停、更新、卸载和创作中心分发。通用能力缺口只补公开 SDK，不增加私有宿主接口。不建设调试、追踪、检测平台，不实现递归团队、跨设备团队或新的工作流引擎。

## 开发约束

在 `D:\GIT\mohists` 单线程开发，直接在项目目录测试。不创建隔离环境或仓库副本，宿主与 SDK 引用已有 mdo，仅部署约 9 MiB 应用文件到唯一运行目录。每个小阶段测试通过后提交 commit。禁止把密钥、生产数据、用户会话放入插件或仓库。

## 2026-10-26：原生成员执行与消息

- 已接入 `mohists_team`、`mohists_mail` 模型工具；显式执行原生多轮成员，复用父会话模型和实时权限；同一成员的模型绑定在首次分派时固定。
- 执行前以事务预留成员名额和累计成员轮次预算，最多三个成员且最多一个写入成员；重复执行被拒绝。
- 原生结果保留完整引用和截断标记，插件不复制结果账本。任务组代次纳入元数据键，避免新任务组重用任务 ID 时撞到旧数据。
- 定向消息幂等投递、显式确认，不触发模型。消息保留用户/Agent 来源，成员只能消费自己的邮箱。
- `tests/test_execution.py` 通过实际 XS/TCC 和本地 HTTP 模型：多轮上下文、依赖、只读工具、预算、结果和工具调用；零供应商模型请求。
- 停止、约束修订、明确恢复、后台调度、聊天界面和分发回归仍待后续阶段，当前不作为完整版本。

## 2026-10-26：停止与约束修订

- 增加单成员取消、全组停止、完成任务组、修订目标。先关闭新任务准入，再取消并等待活跃成员退出后释放名额；新任务组不继承旧成员上下文。
- 在实际模型请求和工具执行边界校验任务是否仍然有效，防止“预留后、启动前取消”导致迟到执行。自定义绑定角色同样受该协作范围约束；普通 Agent 不受影响。
- 墨者主角色在写入成员活跃期间不能同时写工作区；委派不能绕开墨者的团队预算。约束变化后旧结果保留但标为 stale，不能继续推动新任务。
- `tests/test_control.py` 已用实际原生成员与异步操作验证单写入者、运行中取消、退出收敛、约束变化与新任务组复用 ID。
- 仍需实现显式崩溃恢复与后台队列，再进入聊天界面阶段。
